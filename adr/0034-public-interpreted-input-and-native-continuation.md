# ADR 0034: Public interpreted inputs and native conversation continuation

ADR 0036 refines local recovery classification: `source_binding` is repairable
only for an explicitly public, nonsensitive field when an already offered
visitor value passes its published literal or enum binding and schema. This
diagnostic does not admit the proposed value. Missing protected evidence and
policy boundaries remain non-repairable; no public-read default is loosened.

Status: Target decisions accepted by the authorized implementation order on 2026-09-28. S1 through S6 implemented as unreleased package candidates on 2026-09-29. S7 remains planned; host, model and user acceptance remain open.

## Decision and implementation boundary

The target contract is section 3 of [the runtime-generalization plan](../archive/plans/2026-09-28-runtime-generalization.md). Acceptance of that target does not activate unimplemented slices or promote the candidate statuses of ADRs 0031 through 0033 to released behavior. The S1 field-policy, S2 continuation, S3 recovery and S4 authoring rules below are executable in this candidate.

### S1: One published field policy and one admission owner

An immutable Connector operation may explicitly publish `source=interpreted` with `field_role=public_domain` and `exact_source_required=false` for reviewed public, nonsensitive read arguments. Neither GET, MCP read hints nor a field name supplies that positive review. Authors classify fields within `metadata.input_policies`; all other roles and unclassified fields retain their existing source rules. The reviewed operation, fixed Connector environment and field policies are hashed and pinned together.

`metadata.input_policy_preset=public_interpreted_read.v1` is mutable authoring data only. The existing publisher expands it into canonical field policies for explicitly declared `public_domain` fields without an explicit source. It is absent from published operation metadata and Agent pins. An explicit source remains authoritative; contradictory exact binding, resolver, alias, continuation or rebinding options fail publication. No runtime profile flag or second policy store exists.

The existing `AgentConnectorInputBinder` admits model interpretations against the published schema, including enums, finite numeric ranges, length and pattern constraints, nullable values, bounded arrays and closed objects. This proves schema validity, not semantic correctness. Language, provider and domain vocabulary do not select a Core branch. Missing or ambiguous values can still be omitted and asked about naturally. `search_query` retains its separate bounded search and refinement contract.

Policies use published paths such as `filter.unit` and `units[]`. An interpreted parent never transfers its relaxation into a child: each interpreted child needs its own positive policy. Explicitly protected ancestors exclude interpreted descendants. Existing literal trees keep their existing source admission. Arrays remain bounded by 25 items, and interpreted object structures are closed. Unsupported schema keywords fail publication. Nullable schemas use the existing `nullable` representation; null, absence and an explicit draft unset are distinct.

Credentials, request headers, sensitive query values, arbitrary destinations and URL/URI fields, tenant/actor scope, private targets, canonical read dependencies, confirmation values and write payloads cannot obtain this policy. All incoming read dependencies reject interpreted targets. A public interpreted read never grants authority to a later Write or substitutes for a resolver selection, identity proof or confirmation.

The adapter and Gateway call the same binder through existing context admission. The Gateway additionally checks the exact published revision, input policies, schema, strategies and environment, and rechecks interpreted source binding before dispatch. Hash-valid but changed policy pins cannot replace the operation revision's policy. Closed deployment authority, denied-read policy, Write permission, confirmation, idempotency, redaction and unknown-effect reconciliation remain authoritative.

Interpreted provenance has server-owned `kind=model_interpreted`, policy version/hash, value hash, operation hash, capability, visitor message/context hash, source turn and authority-scope hash. Fresh execution requires the persisted active turn. S2 binds fresh interpretations to the current visitor message plus the visitor messages in the actual bounded native history offer. Reverified retained values retain their original visitor sources through the existing encrypted Connector context; provenance is recomputed, not stored in a second task record. The provenance enters the Gateway outcome and canonical tool execution trace. It is neither verified identity nor visitor approval. The shared Binder continues to own literal, resolver and read-evidence admission.

Diagnostics distinguish `missing`, `schema`, `policy` and `evidence` failures. `input` keeps the root field used by existing draft owners, while `field_path` carries the exact published child/index path and `rules` carry bounded schema codes. Rejected values are not diagnostic data. Undeclared top-level provider convenience arguments retain the existing discard rule; they cannot satisfy a required field, supply authority or enter dispatch. Unknown nested paths and unknown policy paths are rejected. S5 projects bounded, registered field causes through the existing activity, inspector and export. Historical events without those fields remain unknown.

### S2: One offered visitor context and compact draft selection

S2 retains `AgentConversationState` and the existing encrypted Connector context as the sole draft owner. Fresh interpreted proposals may use the bounded visitor history actually offered to the model, identified by a server-owned context reference. Assistant prose, tool content and summaries cannot become approvals or protected-field sources. A short server handle encodes the current task identity and revision, resolves against the existing owner, and is rechecked through the same admission at the Gateway before dispatch. Ordinary public read controls become exactly one optional `__request` object with `handle`, `action=continue|revise|cancel` and an optional list of published paths to unset. No handle means independent input, with no implicit field inheritance. Omission on a selected draft retains the field; an invalid explicit correction prevents dispatch of the old value. Stronger dependency, resolver and confirmation proofs remain conditional offers for the capabilities that require them. Ordinary question prose requires no durable task or quoted question mark. Canonical selection and confirmation delivery proofs remain.

Native history retains at most twelve previous visible conversation messages, subject to smaller published history and token limits. The visitor-only references are captured from exactly those message objects after preflight compaction; the current visitor message is appended. Summaries, assistant and tool text add no input authority. Server-owned `offered_visitor_context.v1` provenance hashes those ordered message IDs/content hashes. Each retained interpreted field keeps its original historical references in the existing encrypted source entry, without another task or provenance store. Reload rechecks each source message, source turn, deployment and scope. Task TTL is not renewed.

The compact protocol is derived from the pinned interpreted field policies, never a saved runtime option. Public interpreted tools reject the replaced `__pending`, `__rebind`, `__unset` and manual request-evidence path. Tools with declared conditions or protected selection/dependency inputs retain only their necessary additional controls. The separate cancellation tool excludes compact public drafts. Historical `__prior_read` handles remain result references and cannot be combined with `__request`. Invalid schema corrections can retain an inert draft with valid partial values and unresolved fields, but no question, offer or execution. Its new revision invalidates stale handles.

### S3: Typed outcomes and one native Stop repair

S3 uses typed execution evidence to distinguish local correctable schema/protocol failures, genuine missing input, missing protected evidence, definitive policy/capability boundaries, successful/no-match reads, provider failures and unknown effects. After a local, nonexecuted correctable read, one ordinary Stop may receive a native repair chance using the existing two recovery credits, original step ceiling, deadline and usage budget. At most one Stop repair is allowed per turn; it does not force a tool or success, and a genuine needs-input question does not trigger it. Another Stop without material progress ends with unresolved read status. This candidate explicitly supersedes ADR 0031, Decision, ordinary complete-text termination, only for that bounded local repair. A repeated ordinary Stop ends unresolved work, including an empty repeated Stop. Length, Empty, answer-only and Stop recovery share the same two credits across restarted provider step numbers. No outer loop, universal answer reviewer, Claims JSON or prose/regex state classifier is introduced. Read execution and job status come only from Gateway evidence.

The existing ConversationState owns the latest observation per selected operation. Genuine input needs, missing protected evidence, policy boundaries and Gateway outcomes settle its local repair eligibility. Inert schema drafts remain local corrections. The bounded v3 observation snapshot records `outcome_class`; v1/v2 remain historical readers. Unknown execution retains `reconcile` even after presentation feedback. Empty successful result lists are no-match evidence; a provider 404 remains a failed provider lookup, not proof of absence.

The existing native adapter canonicalizes proposals without provider call IDs and binds replay to its immutable tool/deployment/scope/turn, selected operation and exact draft controls (including revision). Identical correlated repairs return their existing rejection or result. A different task or a published explicit refresh retains normal admission; no persistent cache or cross-turn duplicate lock is introduced. Connector admission/result reuse continues to use the existing Binder and Gateway. Feedback names affected fields and their required status under the already offered schema instead of repeating the complete tool definition. The last native composition sees observed execution states and evidence references. Continued Stop prose is suppressed by the existing stream buffer and is not the canonical response.

### S4: Explicit author review and the same model offer

MCP and OpenAPI imports remain inactive drafts with strict literal/enum field policies. The native Operation workbench offers an explicit public read profile, per-field roles and a publication preview against the current immutable revision (or the strict default for a new operation). The form's `profile` source choice is removed before storage. Only the existing Publisher expands the author preset into canonical field policies. Explicit existing sources remain authoritative; conflicting exact evidence, aliases, protected roles and Write constraints still fail publication. Nested paths and array-item paths require their own reviews. Preview, normal testing and publication never mutate prior operation revisions or Agent deployments.

OpenAPI local references and supported required, enum, nullability and nested facets survive import. Unsupported input compositions/facets remain visible in the inert draft and fail the existing publication validator with their field path; no branch is selected or flattened. MCP accepts the equivalent single typed null union. Nullable values still obey enum/const restrictions at the existing validator. Optional query/header/MCP arguments remain absent before template resolution, even when an older Playbook variable has the same name. False and zero remain present. Unsupported optional whole-body omission mapping fails import explicitly instead of changing optional to required. Direct Agent schema defaults retain the existing rejection; use published fixed templates or documented provider omission behavior.

Native tools describe the operation purpose, field source/required status, mapped visible result paths/labels, fixed result-window limits and applicable controls. Hidden fields are excluded. Complete result metadata remains in the canonical result contract. Shared example/default rules appear once in Agent instructions. Existing SDK constraint guidance and provider adapters remain the sole wire projection; admission and usage use that exact offer. No new schema compiler, semantic model, Binder or state owner is added.

### Accepted targets for later slices

S5 projects existing events for diagnostics. S6 verifies the deterministic domain-independent matrix without claiming model language quality. S7 performs separately authorized real host/model/widget acceptance. No later slice may create a second runtime authority or infer an unlimited live-test budget.

## Compatibility

New Agent publication pins runtime ABI v23 and compiler ABI v16. Existing artifacts remain immutable and readable as historical records, but do not execute through a legacy fallback under the new ABI. The canonical operation contract remains v3 with the explicit new source/role schema. Republish affected operations and consuming Agent candidates normally; dependent Playbooks need their normal repinning when operation pins change. No schema migration, Live pointer mutation, host switch, live inference, activation or package publication occurs in S1 through S6. The existing encrypted envelope advances to v5; v3/v4 remain historical readers. No database migration is required.

## Simplicity and ownership

The sole new class, `ConnectorInterpretedInputPolicy`, validates the positive review and enumerates published schema paths for the existing contract/publisher/Binder. It owns no interpretation, execution, persisted state or routing. The existing Publisher expands authoring options; the Binder remains the only input admission owner; `AgentConversationState` remains the only draft owner; the Gateway remains the only external execution owner. The existing SDK lifecycle owns the bounded S3 exception; AgentGraph transitions and canonical Turn commit retain their owners. S2 introduces no new class or state owner. It removes the public legacy controls, source-echo injection and separate cancel offer for compact drafts. References extend existing source entries; the native snapshot remains ephemeral. Stronger capabilities retain their distinct proof contracts. S3 adds no product class, Loop, Binder, state store or model reviewer. It removes duplicated pending-repair scanning from DeployedAgent and full-schema error feedback. Subsequent slices must continue to remove replaced controls and overlapping paths, not add a permanent second route.

S4 adds no product class, runtime control or policy store. Its form-only profile source expands at the existing Publisher. Result fields/window are derived from the immutable response contract. The shared request planner now omits absent optional inputs for HTTP and MCP. Silent OpenAPI facet filtering, `allOf` flattening, optional-body-to-required conversion and repeated example/search instructions are removed. The Binder, native SDK projection, Gateway and state owners retain their authority.
